# KeyGuard 商业接口预留说明（未实现）

本文只记录未来网站前端与商业服务之间可能采用的接口边界。本次改版不包含 API 服务、订单存储、支付接入、回调处理或激活码签发，也不应在静态页面中模拟这些结果。

## 页面当前行为

- 页面展示 ¥6.8，一次性购买、永久授权；购买咨询通过真实微信号 bunny1442 和随页面提供的真实二维码承接。
- 不发送订单请求、不显示二维码支付流程、不生成订单号、不展示支付成功页面，也不生成 DEMO 激活码。
- 页面展示用户提供的真实软件截图、微信二维码，以及从免责声明 DOCX 原文整理的完整使用说明。
- 正式 ZIP 客户端尚未确定；不提供下载链接、大小或 SHA256，也不把管理员激活码工具作为客户端。

## 未来接口候选

| 方法 | 路径 | 预期职责（待后端方案确认） |
|---|---|---|
| POST | `/api/v1/keyguard/orders` | 创建待支付订单，服务端返回订单编号及支付信息 |
| GET | `/api/v1/keyguard/orders/{orderId}/status` | 查询订单状态 |
| GET | `/api/v1/keyguard/licenses/retrieve` | 经订单核验后取回真实授权材料 |
| GET | `/api/v1/keyguard/release/latest` | 获取正式发布版本元数据和下载信息 |

上述路径目前只是接口预留，不保证最终合同、字段或安全流程。实现前需明确订单身份核验、支付服务端回调验签、重复通知处理、授权取回身份验证、限流和隐私告知。浏览器端不得保存支付密钥、签发私钥或信任仅由客户端提交的“支付成功”状态。

## 建议的前端接入边界

未来可以在 KeyGuard 页面单独加入 `src/lib/keyguardCommerce.ts` 一类的请求封装，并由明确的用户操作调用。页面暂不创建该文件或请求函数，避免把未启用的支付能力混入当前静态站点。

## 隐私边界

客户端本地输入处理与本地诊断日志属于软件运行数据。若未来接入购买、支付或订单取回，服务端可能处理完成交易所必要的订单标识、支付状态及用户提供的联系方式等信息；需在后端上线前单独确认并发布对应隐私说明。
